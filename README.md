# SpriteLoop

**输入一张图，让游戏角色循环动起来。**

面向 PC 的游戏动画工作台：上传首帧 → 方舟 Seedance 生成纯色背景视频 → 首尾相接无限循环预览与人工确认 → 等间隔 / 运动关键帧采样 → 移除纯色背景 → 透明 PNG、Sprite Sheet + JSON 与 WebP 导出。

## 运行

需要 Node.js 22+、pnpm 11+。FFmpeg 与 FFprobe 随依赖安装，也可用环境变量指定现有二进制。

```sh
pnpm install
cp .env.example .env
# 可在启动后打开「设置」填写火山方舟 API Key，也可使用 .env 的 ARK_API_KEY
pnpm dev
```

打开 http://localhost:3100 。服务仅监听本机 `127.0.0.1`。本次本地环境已配置密钥，无需覆盖 `.env`。

```sh
pnpm test       # 参数契约、纯色抠图算法、真实 FFmpeg/图集/动画时长测试
pnpm build     # TypeScript 检查 + Vite 生产构建
pnpm start     # 使用生产构建
```

## 使用

1. 上传 PNG、JPEG、WebP 原画，或点击「使用示例」。每张 ≤ 20 MB，宽高 300–6000 px，宽高比 0.4–2.5；保留原始 Alpha。发送给模型时，将透明区域合成所选背景色，默认白色，可选绿幕绿（#00FF00）或自定义颜色。
2. 输入动作，选择模型、4 秒及以上的时长和分辨率。只需上传一张原画，服务端固定使用同一张图片作为首帧和尾帧，不提供单独尾帧输入。
3. 点击「生成动画」调用真实方舟接口。状态、提供方任务 ID、输入和参数保存到本机。刷新后在「历史记录」恢复任务及原画。
4. 视频生成后进入 `awaiting_review` 状态，不自动抽帧。将完整视频首尾连接为三轮连续预览，再由浏览器无限循环播放；不做倒放、补帧或淡化接缝。检查尾帧回到首帧时的姿态、位置与速度，点击「确认连贯，提取序列帧」后才开始转换；确认记录保存在任务中。
5. 等间隔采样用于连续动画；关键帧模式在指定 FPS 下按画面差异去重，记录可变帧时长。它是运动内容采样，不是只提取视频编码的 I 帧。
6. 调整移除纯色背景容差、柔化、内部同色保护或导出尺寸，点击「应用设置」。这一步复用已保存的视频，不会调用模型。
7. 透明序列帧默认无限循环播放，可暂停逐帧检查，然后下载完整素材包、PNG 序列、或 Sprite Sheet + JSON。可直接导入已有视频（≤150 MB、≤60 秒、最高4K）进行本地处理。

## 历史记录与素材库

- 「历史记录」按时间倒序展示生成和导入任务，支持按动作、模型、任务 ID 搜索及状态筛选。点击记录恢复原画、动作描述、模型、时长、分辨率、背景色和采样设置；新记录保留创建时的处理参数及提示词模板，恢复不会自动调用模型。旧记录没有初始处理快照时，使用最后保存的处理参数。
- 「素材库」的原画页自动收录上传图片，支持新增上传、下载及「用作首帧」。动画页收录已保存视频和透明序列帧，可打开继续预览、处理和导出。
- 上传图片和任务持久化在本机 `data` 目录。历史模板只作用于恢复后的工作台，可通过恢复提示中的按钮改用设置里的最新模板。

## 工作台设置

顶部「设置」可编辑统一生成提示词模板，以及保存或更换火山方舟 API Key。所有 Seedance 模型共用同一密钥；输入框留空会保留现有密钥。设置密钥优先于 `.env`，仅保存于忽略提交的 `data/settings.json`（权限 0600），接口只返回配置状态，不返回密钥；无需重启服务。

模板包含 `{{action}}`（动作描述）、`{{background}}`（背景名称）和 `{{background_rgb}}`（背景 RGB）。动作和背景 RGB 变量必须保留。设置里可预览当前动作与背景色渲染后的完整提示词，并恢复默认模板；模型请求不再附加模板以外的隐藏提示词。新任务保存创建时的模板，修改设置不会改变已有任务。首尾同图、模型、时长、分辨率、音频和水印等仍由请求参数控制。

## 模型接入

使用 [创建任务 API](https://ark.volcengine.com/region:cn-beijing/docs/82379/1520757?lang=zh) 和 [查询任务 API](https://ark.volcengine.com/region:cn-beijing/docs/82379/1521309?lang=zh)，通过服务端 Bearer 鉴权。首尾帧使用 `content[].role: first_frame / last_frame` 和 PNG Base64。视频成功后立即保存到本机，避免依赖有时效的下载链接。

| 模型                              | 工作台视频分辨率    | 工作台时长 |
| --------------------------------- | ------------------- | ---------- |
| `doubao-seedance-2-5-260628`      | 480p / 720p / 1080p | 4–30 秒    |
| `doubao-seedance-2-0-mini-260615` | 480p / 720p         | 4–15 秒    |
| `doubao-seedance-2-0-fast-260128` | 480p / 720p         | 4–15 秒    |
| `doubao-seedance-2-0-260128`      | 480p / 720p / 1080p | 4–15 秒    |
| `doubao-seedance-1-5-pro-251215`  | 480p / 720p / 1080p | 4–12 秒    |
| `doubao-seedance-1-0-pro-250528`  | 480p / 720p / 1080p | 4–12 秒    |

参数按 2026-09-15 官方文档核对。较新模型仅用提示词约束镜头，不发送其不支持的 `camera_fixed`。1.0 Pro 不发送 `generate_audio`。本版未开放 2.0 的 4K 生成选项。

实际账号权限由方舟决定；一次请求只调用所选模型，不会静默降级到其他型号。API Key 仅存储于被 Git 忽略的 `.env`，不写入浏览器或产物。

## 数据与导出

- `data/assets/`：上传原画和素材记录。
- `data/jobs/<job-id>/job.json`：任务参数、状态、提供方 ID、使用量和产物引用。
- `data/jobs/<job-id>/source.mp4`：已保存的生成或导入视频。
- `data/jobs/<job-id>/render-*/`：各次帧处理结果。

所有 `data/` 内容均被 Git 忽略。服务重启恢复未完成任务；已取得提供方 ID 的任务重试时不会重新创建视频。提交期间中断且未获得 ID 的任务需先在方舟控制台确认，避免重复生成。

素材包包含 `frames/0000.png` 等透明帧、`spritesheet.png`、`spritesheet.json`、`manifest.json`、`preview.webp`。所有帧画布尺寸一致，图集不旋转、不裁边，锚点为中心 `(0.5, 0.5)`。元数据明确记录每帧 `duration_ms`，与 WebP 动画使用相同时间信息。WebP 编码器可能合并完全相同的画面并累加时长。

## 验证与边界

已使用生成的游侠示例原画，通过浏览器真实提交 Seedance 1.5 Pro 首尾帧任务（4 秒、480p、无声）。实际视频为 640 × 640、4.042 秒；12 FPS 等间隔提取 49 帧，运动关键帧去重后 47 帧，输出 512 × 512。逐帧检查确认全部帧包含透明与不透明像素，图集可还原逐帧画面，WebP 与元数据总时长均为 4042 ms；三种 ZIP 格式通过完整性检查。

其他五个模型完成官方参数核对和请求契约测试，未逐一进行付费生成。示例图是 AI 生成素材，不是用户上传的实际游戏资产。

本版是本机单用户工作台，尚未部署公网或加入多用户账户系统。纯色背景、角色一致性和自然循环依赖模型输出，不能保证；`loop_quality` 保持 `unreviewed`，首尾图相同不代表已通过无缝循环验收。边界连通移除纯色背景尽量保留内部同色细节，也可能保留封闭的背景区域。尚未实现自动对齐、自动修复接缝和游戏引擎实机验收。

最多采样 360 帧、图集最多 9000 万像素，超限会提示降低采样 FPS 或输出尺寸。所有效果应在导出前预览检查。

## 结构

- `src/components/`：原画设置、预览播放器、时间轴、处理与导出、作品库。
- `server/catalog.mjs`：六个型号的能力与请求约束。
- `server/ark.mjs`：方舟服务端适配。
- `server/processing.mjs`、`server/matte.mjs`：真实 FFmpeg 解码、差异采样、移除纯色背景、图集和动画导出。
- `server/storage.mjs`：本地任务与素材存储。
