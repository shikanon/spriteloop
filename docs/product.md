# SpriteLoop 产品需求

## 目标

让游戏开发者从一张静态图片获得主体一致、画布稳定、首尾衔接自然的游戏动作序列帧。首个验收流程聚焦单主体待机循环。

## 用户流程

1. 上传本地图片，看到预览、尺寸和透明通道状态。
2. 选择待机动作并填写补充描述；设置目标帧数、FPS 和画布尺寸。
3. 提交任务，看到处理状态；失败时显示原因并允许使用原输入重试。
4. 查看连续循环与逐帧预览，调整播放帧率；生成参数变化时创建新任务。
5. 下载素材包，并在外部播放器或游戏引擎中验证播放效果。

## 输出

| 文件 | 用途 |
| --- | --- |
| `frames/0000.png` 等 | 从 0 开始编号、统一尺寸的 RGBA 帧 |
| `spritesheet.png` | 按帧顺序排列的透明图集 |
| `spritesheet.json` | 图集帧矩形、帧时长、锚点和循环设置 |
| `preview.webp` | 循环动画预览；实际编码支持需在实现时验证 |
| `manifest.json` | 原始素材引用、请求参数、实际输出参数和产物清单 |

## 验收标准

- 输入来自用户上传的真实图片；演示素材、模拟结果和真实模型生成要明确区分。
- 主体轮廓、配色、装备和画风在动作中保持一致；人工检查无明显多肢、闪烁或穿帮。
- 连续播放至少 5 个循环，人工检查循环接缝没有明显跳变或停顿；不得仅靠复制首帧宣称无缝。
- 所有帧尺寸一致，主体不被意外裁切，固定锚点下没有非预期位置漂移。
- 输出透明背景时，检查所有帧的 Alpha 和边缘，避免背景残留或主体被误删。
- 实际帧数与导出元数据一致，图集帧矩形不重叠、不越界，可还原原始帧序列。
- PNG 序列、图集和预览的帧序及时间参数一致；在浏览器以外的播放器或游戏引擎复核。
- 测试记录包含输入、模型及版本、请求参数、实际输出参数、耗时、结果和失败原因。
- 不支持的输入或参数应明确报错；模型实际输出与请求不一致时必须显示差异。

## 后续范围

扩展行走与奔跑、自定义动作、多方向、批量生成和游戏引擎专用导出。首版不包含模型训练、骨骼编辑器或完整游戏制作。
