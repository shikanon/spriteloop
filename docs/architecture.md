# 技术分层与数据约定

本文是待实现的设计约定，不代表现有可运行接口。

## 处理链路

本地图片上传 → 素材存储 → 生成任务 → 模型适配器 → 解码与采样 → 背景处理与帧对齐 → 循环检查 → 预览与导出。

## 模块职责

- **工作台**：上传、动作与参数配置、任务状态、逐帧检查、循环播放和下载。
- **素材管理**：保存原图并返回 `asset_id`，后续任务复用已上传素材；临时下载地址不作为永久标识。
- **任务服务**：管理 `queued / running / succeeded / failed`，保存阶段、时间、输入、参数、结果和错误。
- **模型适配器**：声明支持的输入类型、尺寸和时长，将任务转换成提供方请求；未支持的参数必须显式拒绝。
- **帧处理**：解码生成结果、确定采样策略、处理 Alpha、稳定画布与锚点，并检查主体裁切。
- **循环处理**：检查末帧到首帧的外观和运动连续性；重生成、拼接或其他修复需要可追溯。往返播放不能冒充自然循环。
- **导出器**：生成 PNG 序列、图集、元数据和预览，并校验尺寸、顺序与帧数。

模型选型前需用同一批真实输入评估动作可控性、主体一致性、首尾衔接、背景处理难度、延迟和成本。

## 数据约定

- `Asset`：素材 ID、存储位置、文件类型、宽高、是否含 Alpha。
- `GenerationJob`：任务 ID、素材 ID、动作描述、请求帧数/FPS/尺寸、模型及版本、实际生成参数、任务状态、结果引用与错误。
- `AnimationManifest`：版本、任务 ID、帧序列、实际 FPS、画布尺寸、锚点、循环播放设置和产物清单。

播放是否循环与视觉接缝是否合格是两个独立字段：`loop` 表示播放行为；`loop_quality` 使用 `unreviewed / passed / failed` 表示审核结果。

首版采用固定尺寸网格图集、不旋转、不裁边；坐标以图集左上角为原点，单位为像素。锚点采用单帧画布内的归一化坐标，左上为 `(0, 0)`、右下为 `(1, 1)`。每帧显式记录 `duration_ms`，避免播放器推断造成时间差异。

## 实施顺序

1. 模型效果验证，记录可行方案与限制。
2. 原图持久化、单任务真实生成与失败恢复。
3. 帧标准化、循环预览、导出与一致性检查。
4. 接入工作台并完成真实用户流程验收。

密钥仅由服务端配置，素材与生成产物不提交到代码仓库。第三方模型或存储地址的传递由适配层处理，前端不接触提供方密钥。
